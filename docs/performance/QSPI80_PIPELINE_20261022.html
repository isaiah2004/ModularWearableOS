Twice the bus clock halves only the ideal payload time.

The ideal model assumes four data bits per clock and no command, turnaround, scheduling or inter-chunk gaps. The actual transfer envelope can be longer.

speedup = 1 / ((1 − f) + f / 2)

Here f is the fraction of the original critical path that the faster bus can accelerate. Doubling a stage that occupies half that path gives 1.33× overall speedup. This is an example, not a fitted result for this watch.

How to read these timings
  • Raster wall (inclusive) is the engine’s raster timer, including measured stripe-buffer waits and nested work. Subtracting those waits gives a useful residual wall time; CPU cycles were not isolated.
  • Loop start → render return also includes earlier input and housekeeping work, so it is broader than the three engine timers.
  • Transfer window runs from the first LCD API entry to the last DMA callback. It includes command and starvation gaps; no continuous wire-busy signal was captured.
  • Frame complete means the final DMA fence passed and pixels reached panel GRAM. Panel scanout and photon timing were not captured.
  • Parallel stages cannot be added into a serial total. Timeline envelopes and worker totals are deliberately shown separately.
